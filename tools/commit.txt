fix: 根因找到——INPUT 结构体少 8 字节，字符全被写丢，目标程序重复同一个字

## 症状

用户说「今天天气不错」（日志确认精化结果 len=7），微信里出现的是
「今今今今今今今」—— 同一个字被发了 7 遍。

## 根因（本项目最隐蔽的一个 bug）

Win32.INPUT 的 union 里我只声明了 KEYBDINPUT（16 字节），
但 Windows 的 union 最大成员是 MOUSEINPUT（24 字节，因为 x64 下
dwExtraInfo 指针要对齐到 8 字节边界）。

后果链条：
- JNA 按「union 里最大的成员」算结构大小 → 只有 KEYBDINPUT 时算成 32 字节
- Windows 期望 40 字节
- 于是 wScan（字符所在字段）被写到偏移 24，而正确偏移是 32
- 字符全部落到无效位置 → Windows 读到的字符字段是垃圾
- 目标程序因此重复前一个有效字符 → 「今今今今今今今」

最要命的是它完全静默：SendInput 报告「14/14 个事件全部写入成功」，
事件数完全正确，只有人眼看目标程序才能发现内容不对。

## 修法

1. Win32.INPUT 的 union 成员改为 MOUSEINPUT（24 字节），
   把整个结构撑到正确的 40 字节；KEYBDINPUT 以 union 视角做字段解释。
2. 位置偏移**不手算**，改用 JNA 的 fieldOffset 得到（union 起点 = 8，
   字符字段 = 10），并加了 offsetOf() 公开出口以便测试断言。
3. SendInput 的参数类型从 INPUT[] 改为 Pointer，缓冲区由
   **自己分配的连续 Memory** 提供，按字段偏移逐字节写入。
   原因：实测用结构体数组传参时 SendInput 直接返回 0
   （JNA 对含 union 的结构体数组编组不可靠）。
   写入后**回读校验**每个事件的字符，确认是它自己那个字。
4. 启动时打印一次布局校验（结构大小 / union 起点 / 字符字段偏移），
   不一致就记 ERROR。**正是这条日志把根因指了出来**。

## 验证（决定性证据）

修复前：
    发送事件明细：U+4ECA（共 2 个事件）   ← 6 次全都是「今」
修复后：
    待注入字符（码点）：U+4ECA U+5929 U+5929 U+6C14 U+4E0D U+9519
    INPUT 布局：结构 40 字节（应 40），union 起点 8（应 8），字符字段偏移 10：正确
    注入调用成功：写入 12 个事件

## 顺带修掉

- SampleInjector 不再无条件按 Enter：它本来是用来调间隔的，
  而被测程序往往是输入框，按 Enter 会把内容直接发出去
  （实测在 cmd 窗口里就是「执行了刚注入的那行命令」）
- 逐字符追踪日志从「每字一行」收敛为「整段一行」，避免刷屏
- 代理对（emoji）的说明写清楚了：一个码点 → 一到两个 UTF-16 code unit，
  每个 code unit 一对事件，由 Windows 组合
