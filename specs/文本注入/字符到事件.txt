# 规格：注入分账（text.TextInjector.plannedEvents）
#
# 意图：钉住"应当写入多少个键盘事件"这个**独立基准** —— 它是「出口诚实」的地基：
#   实收 < 基准 就要报 PARTIAL_WRITE 失败（而不是报成功），见 docs/DECISIONS.md D2。
#   基准算错的后果是双向的：算多了 → 每次注入都误报失败；算少了 → 丢字仍报成功。
# 来源：docs/IMPLEMENTATION-STATUS.md §3.1 第 21 条；docs/待处理问题.md 1.1（已修）。
#
# 规则（一句话）：事件数 = 2 × 文本的 **UTF-16 单元数** + 2 × max(0, 退格数)
#   - 每个 UTF-16 单元一次按下 + 一次抬起 = 2 个事件（这是 Windows 的既定行为）
#   - 代理对（如 emoji）是**一个码点、两个 UTF-16 单元** → 4 个事件
#   - 本函数**不**过滤控制字符：调用方必须传"真正要发出去的那份文本"
#     （注入器先过 TextUtils.withoutControlChars 再算基准，见下表最后两行）
#
# 语法（每行一个用例，用 | 分列；# 开头是注释，空行忽略）：
#   用例名 | 文本 | 退格数 | 先过滤控制字符 | 期望事件数
#   - 文本里的 \n 写成 \n 两个字符（由测试自行还原）；(空) 表示空串
#
# 改动规程：**改本文件 = 改规格**。必须走 [SPEC] 提交，并在 docs/DECISIONS.md 记一条。

空文本 | (空) | 0 | no | 0
ASCII 短句 | hello | 0 | no | 10
三个汉字 | 今天天 | 0 | no | 6
代理对：一个码点两个 UTF-16 单元 | 😀 | 0 | no | 4
一个退格 | (空) | 1 | no | 2
两个字加两个退格 | 今天 | 2 | no | 8
负退格按 0 计（否则基准会变成负数，写少了永远判不出来） | 今 | -5 | no | 2
控制字符不会被自动剔除（谁调用谁负责传过滤后的文本） | a\nb | 0 | no | 6
实发文本是过滤后的那份，基准必须用同一份 | a\nb | 0 | yes | 4
