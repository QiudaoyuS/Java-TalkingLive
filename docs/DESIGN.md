# TalkingLive 产品设计文档

> 版本 0.1 ｜ 状态：设计中 ｜ 目标平台：Windows

---

## 1. 产品定位

**一句话**：一个常驻后台的 Windows 语音输入工具。说出唤醒词后，你讲的话会实时出现在**任意应用**的光标处。

**核心价值**：把「打字」换成「说话」，但不改变你现有的工作流——它不要求你在某个特定软件里工作，文字直接进你正在用的那个程序。

**目标用户**：项目作者本人（自用优先）。

**与现有方案的差异**：

| 方案 | 局限 |
|---|---|
| 系统自带语音输入 | 需按住热键、唤醒词不可自定义、无结束词与自动发送 |
| 云端听写服务 | 需联网、麦克风音频上传云端 |
| **本产品** | 完全本地、语音唤醒、结束词与发送键可配、注入任意应用 |

## 2. 核心交互

### 2.1 状态机

```
        ┌──────────────────────────────────────────────┐
        │                                              │
        ▼                                              │
   ┌─────────┐    听到唤醒词     ┌───────────┐          │
   │  IDLE   │ ───────────────▶ │ LISTENING │          │
   │ 待唤醒  │                  │   听写中  │          │
   └─────────┘                  └───────────┘          │
        ▲                             │                │
        │                             │ 结束词 / 静音超时 / 切窗口
        │                             ▼                │
        │                       ┌───────────┐          │
        └───────────────────────│ COMMITTING│──────────┘
                                │   提交中  │
                                └───────────┘
```

任何时刻只处于且仅处于一个状态。该状态机是程序骨架。

### 2.2 一次完整使用

1. 程序常驻后台，托盘图标显示「待唤醒」
2. 你在任意应用里，把光标放到想输入文字的位置
3. 说「子曰」→ 托盘图标变为「听写中」，浮窗出现在光标附近
4. 正常说话，文字**实时出现在浮窗里**（此时目标程序完全不受影响）
5. 说「本段结束」，或静音 5 秒 → 浮窗中的文字**一次性注入**光标处
6. 若开启了自动发送，再模拟一次按键（Enter / Ctrl+Enter）
7. 回到「待唤醒」，等待下一次

> 任何时刻按 **Esc** 可取消整段，一个字都不会打出去。

## 3. 功能范围

### 3.1 MVP

| # | 功能 | 要点 |
|---|---|---|
| 1 | 常驻 + 托盘 | 图标显示状态（待唤醒/听写中/已暂停），可暂停监听 |
| 2 | 配置文件 | JSON：唤醒词、结束词、静音时长、发送键、自动发送开关；启动时校验 |
| 3 | 音频采集 | 单路 `TargetDataLine`，16kHz/16bit/单声道，分发给唤醒检测与识别 |
| 4 | 状态机 | IDLE / LISTENING / COMMITTING，显式建模 |
| 5 | 语音唤醒 | Vosk 受限语法检测唤醒词 |
| 6 | 听写 + 浮窗预览 | Vosk 流式识别；浮窗不抢焦点；Esc 整段取消 |
| 7 | 结束检测 | 结束词 / 静音兜底（默认 5s，可调可关）/ 切窗口 |
| 8 | 文本注入 | `SendInput` + `KEYEVENTF_UNICODE`；**注入前校验前台窗口**；失败须明确提示 |
| 9 | 自动发送 | 触发时机与按键可配，默认**关闭** |
| 10 | 标点 | 段落末尾句号 + 按停顿加逗号/句号（用 Vosk 词级时间戳） |
| 11 | 日志 | 状态流转 + 错误，滚动 5MB×3，**不记转写内容** |
| 12 | 打包 | jpackage 产出 exe |

### 3.2 明确不做

whisper 精修、热词表、多词表切换、历史记录、云端同步、全局热键、多语言、跨平台。

### 3.3 后续规划

| 阶段 | 内容 | 说明 |
|---|---|---|
| 二 | **whisper.cpp 精修** | 段落结束时重跑音频，拿到带标点的更准文本。排在第一位，因为标点质量直接决定可用性 |
| 二 | **热词表（外部来源）** | 可插拔的词表来源，用于提升专业术语识别率与后处理纠错 |
| 三 | **服务端** | 词表云端同步、团队共享、增量下发 |

### 3.4 零成本的接口伏笔

以下三处 MVP 阶段**只留位置、不做实现**，将来均为纯增量扩展：

| 接口 | MVP 实现 | 将来扩展 |
|---|---|---|
| `CommitPolicy` | `WholeSegmentPolicy`（整段注入） | `StablePrefixPolicy`（稳定前缀增量注入） |
| `TextPostProcessor` | `PunctuationProcessor` | `HotwordCorrector`（热词纠错） |
| `TextRefiner` | 原样返回 | whisper.cpp 实现 |

此外，词表 JSON 格式中预留 `version` 字段，供阶段三的增量同步使用。

## 4. 系统架构

### 4.1 分层

```
┌───────────────────────────────────────────────┐
│  UI 层   托盘图标 / 浮窗预览 / 设置界面        │
├───────────────────────────────────────────────┤
│  交互层  状态机 / 会话管理 / 配置              │
├───────────────────────────────────────────────┤
│  处理层  CommitPolicy · TextPostProcessor ·   │
│          TextRefiner                          │
├───────────────────────────────────────────────┤
│  引擎层  WakeWordDetector · SpeechRecognizer  │
├───────────────────────────────────────────────┤
│  系统层  音频采集 / 文本注入 / 窗口监听        │
└───────────────────────────────────────────────┘
```

整个产品是**单进程**，音频与推理全在本地，不依赖网络。

### 4.2 关键设计约束

- **麦克风只开一路**。唤醒检测与语音识别共用同一个 `TargetDataLine`，由采集线程分发。禁止各自开设备。
- **注入器按「批」设计**。接口收整段字符串，内部决定如何分批调用 `SendInput`。整段注入用一次，未来增量注入用多次，调用方无感。
- **字符计数用码点**。涉及「第几个字符」的下标一律用 `codePointCount`，避免代理对导致的退格数算错。
- **浮窗不得抢焦点**。必须 `WS_EX_NOACTIVATE`，且窗口变化事件中显式忽略自身句柄，否则会自我触发「切窗口结束」。

## 5. 关键技术决策

| 决策项 | 选择 | 理由 | 备选 |
|---|---|---|---|
| 交付形态 | 单机 Windows 桌面软件 | 自用优先，无需服务端 | Electron 外壳 |
| 出字策略 | 浮窗预览 + 整段注入 | 避免文字闪烁、撤销栈污染、中间态副作用；支持 Esc 取消 | 直接注入；稳定前缀注入 |
| 识别引擎 | Vosk（流式）+ whisper（精修） | 各取所长：Vosk 管唤醒/结束词/实时预览，whisper 管最终文本与标点 | 纯 Vosk；纯 whisper |
| 文本注入 | `SendInput` + `KEYEVENTF_UNICODE` | 不污染用户剪贴板，兼容性最好 | 剪贴板 + Ctrl+V |
| 触发条件 | 结束词 / 静音 / 切窗口 | 覆盖用户提前结束、忘记说结束词、中途离开三种情况 | 仅结束词 |
| 存储 | 仅 JSON 配置文件 | 明确不要历史记录 | SQLite |
| 打包 | jpackage | JDK 自带，产出带运行时的 exe | launch4j |
| 工具链 | JDK 21 + Maven | 虚拟线程契合音频/识别管线；构建与测试标准化 | 现有 JDK 8 |

## 6. 风险与未验证项

| 风险 | 说明 | 应对 |
|---|---|---|
| **唤醒词能否被识别** | 唤醒词在 Vosk 中文小模型下的命中率**尚未验证**，可能不达标 | Step 0 实测，不达标则换词 |
| **中文识别准确率** | Vosk 小模型准确率有限，可能达不到可用水平 | M2 作为 go/no-go 关卡，不达标则重新评估引擎 |
| **Vosk 无标点** | 输出为无标点长串，影响可用性 | 三级递进：段落句号 → 停顿启发式 → whisper 原生标点 |
| **UIPI 权限隔离** | 目标程序若以管理员运行，注入会被静默丢弃 | 检测失败并提示；必要时以管理员运行本程序 |
| **光标定位不可得** | `GetCaretPos` 在 Chrome / Electron 中常取不到 | 设计降级路径：跟随目标窗口 / 跟随鼠标 |
| **误触发唤醒** | 看视频、开会时被误唤醒 | 选低误触发词；实测验证；提供一键暂停 |
| **引擎集成深度** | 识别引擎是第三方黑盒，不是自研代码 | 价值集中在集成层：低延迟、可切换、流式修正处理 |

## 7. 里程碑

| 阶段 | 产出 | 验证目标 |
|---|---|---|
| **Step 0** | Python 脚本验证唤醒词 | 模型词表是否含该字 + 命中率实测。**可能推翻唤醒词决定** |
| **M0** | Maven 骨架 + 日志 + 配置 + 首批单测 | 工程可构建、可测试 |
| **M1** | 音频采集落成 wav 文件 | 麦克风链路可用 |
| **M2** | 接入 Vosk：唤醒 + 流式识别（先做命令行版） | **准确率与延迟，项目 go/no-go 关卡** |
| **M3** | 浮窗 + 状态机 + 注入 + 切窗口 | 核心难点集中于此 |
| **M4** | 自动发送 + 标点 + jpackage 打包 | 可交付自用 |
