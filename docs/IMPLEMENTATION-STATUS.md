## 4. 怎么验证

```powershell
# ① 环境自检（含模型/词表/注入器/配置/WAV/端到端管线 + 全部自检项）
#    **不碰 UI**（DECISIONS.md D5）：UI 段会如实标成「已按参数跳过」—— 跳过 ≠ 通过
java -cp "target\classes;target\lib\*" com.talkinglive.App --doctor

# ② 完整自检（与 ① 同一套检查；① 多打组件状态行并写 doctor-report.txt）
#    与 ① 的关键区别：② **会跑 UI 段** —— 短暂造悬浮球 + Robot 移动鼠标（别在正用鼠标时跑）
java -cp "target\classes;target\lib\*" com.talkinglive.App --self-check

# ③ 单元测试（不需要麦克风与桌面；**数量见输出结尾，本文不写死** —— 手写常量必然过期）
mvnw.cmd test

# ④ 引擎基准测量（回填 DESIGN.md §6 的数值）
java -cp "target\classes;target\lib\*" com.talkinglive.engine.EngineBench

# ⑤ 引擎冒烟（Vosk 原生库加载 + 词表查询 + 受限语法；这是最容易出问题的一环）
java -cp "target\classes;target\lib\*" com.talkinglive.engine.EngineSmoke

# ⑥ 麦克风实测：实时看音量条 + 预览文字 + 唤醒命中（需要麦克风，15 秒）
java -jar target\talkinglive.jar --mic-test

# ⑦ 真正跑起来（需要麦克风）
java -jar target\talkinglive.jar
```

## 5. 实现过程中发现并修掉的真实缺陷

这些都是**测试或实测抓出来的**，不是设计阶段能想到的。逐条记录以便将来不重犯。

| # | 缺陷 | 后果 | 怎么发现的 |
|---|---|---|---|
| 1 | `vosk_model_find_word` 的返回类型写成指针（C 侧实为 `int` 词 id） | **任何词都返回「在词表内」**，附录 C 的静默失效完全拦不住 | `EngineSmoke` 实测：每个词都返回非 null |
| 2 | 用官方 `org.vosk` 绑定 | 中文语法被按 **GBK** 编码交给按 UTF-8 解释的 Vosk → `Invalid memory access` 崩溃 | `--doctor` 启动即崩 |
| 3 | 受限语法传 `{"phrase_list":[...]}` | Vosk C API 只接受**纯数组** → `Expecting array of strings` + 原生崩溃 | `EngineSmoke` 实测 |
| 4 | 状态机重复 `REFINE_DONE` 放行两次 | **文字被注入两遍** | `StateMachineTest.duplicateRefineDone` |
| 5 | 退格数按 UTF-16 长度算 | 代理对（emoji）会**多退一格**，删掉不该删的字 | `TextUtilsTest.backspacesUseCodePoints` |
| 6 | 全角空格被替换成半角 | 正文出现「今天 天气」多余空隙 | `TextUtilsTest.cleansInvisibleChars` |
| 7 | `endsWithSentencePunctuation` 漏了英文句点 | 「hello.」后面被再补一个「。」 | `TextUtilsTest.sentenceEnds` |
| 8 | 词表校验提示按字段给建议 | 唤醒词出问题时**推荐结束词的备选**，误导用户 | `VoskGrammarTest.adviceIsFieldSpecific` |
| 9 | 无麦克风时的提示**反复弹对话框** | 对话框**盖住悬浮球**，用户连点都点不到（唯一入口失效） | UI 自检的 Robot 右键失败 + `WindowFromPoint` 诊断 |
| 10 | 采集中断后固定 3s 重连 | 日志被刷爆，且加重 #9 的弹窗问题 | 同上；已改退避 3s→30s |
| 11 | 已是目标格式的音频仍做一次 Float 往返 | 引入 ±1 抖动 | `AudioTest.identityWhenAlreadyTarget` |
| 12 | 流式重采样的相位累积每块多吐一个样本 | 长流缓慢多出样本（1 秒多 8 个） | `AudioTest.chunkedMatchesWhole` |
| 13 | **用 `getSourceLineInfo` 去找输入设备** | 枚举恒返回 0 项，于是产品报告「系统没有可用的录音设备」——而麦克风其实是好的、`getLine()` 能直接打开。**用户会以为自己的麦克风坏了，产品完全不可用** | `--doctor` 报「没有可用录音设备」，但 `Win32_SoundDevice` 里明明有 Realtek 声卡；用 `tools/ListMics`/`ProbeMixer` 定位到 `getTargetLineInfo` 才返回 2 项。已改为 `getTargetLineInfo` 并在枚举为空时回退（实测后麦克风立刻可用） |
| 14 | `candidate.open(固定格式)` 写死要 16kHz | 真实设备原生是 44.1k/48k 立体声，硬要 16kHz 会打开失败或让系统做一次质量不可控的重采样 | 同上；已改为 `open()` 用设备自己的默认格式，转换交由 `AudioConverter` 显式完成（TECH-PLAN §7 第 2 项的原始意图） |
