# TalkingLive 交互原型（Demo）

看**界面与操作流程是否合理**用的原型。**没有实现任何真实后端** —— 没有麦克风、没有语音识别、没有 Win32 调用，所有识别结果都是脚本模拟的。

对应设计文档：`../docs/DESIGN.md`

---

## 怎么跑

双击本目录下的 **`run.cmd`**（完整路径：`D:\Program\DeepSeekProgram\Java-TalkingLive\demo\run.cmd`）。

它会依次：编译 → 跑自检 → 启动 Demo。

命令行参数：

| 参数 | 作用 |
|---|---|
| （无） | 正常启动，桌面上只有一颗悬浮球 |
| `--settings` | 启动后直接打开设置窗口 |
| `--auto` | 自动循环演示整段流程（打开设置窗口的「演示」页签） |
| `--ui-test` | 用 Robot 真实右键悬浮球，验证菜单能否弹出，然后退出 |

需要 JDK。本机已验证：`D:\Code\Java\jdk-21.0.12.1`（PATH 里的 `java`/`javac` 已指向它）。

## 界面结构

**启动后桌面上只有一颗悬浮球，没有主窗口。**

```
                     ┌─────────────┐
   悬浮球（常驻） ────▶│ 左键        │ 手动开始 / 结束听写
                     │ 右键        │ 弹出菜单
                     │ 拖动        │ 移动位置
                     └─────────────┘
                            │ 右键
                            ▼
                     ┌─────────────────────────┐
                     │ 手动开始 / 结束听写      │
                     │ 暂停监听 / 恢复监听      │
                     │ 设置...                  │──▶ 设置窗口（常规 / 日志 / 演示）
                     │ 查看日志                 │──▶ 设置窗口的日志页签
                     │ 退出                     │
                     └─────────────────────────┘
```

悬浮球的**颜色就是状态指示**：

| 颜色 | 状态 |
|---|---|
| 深灰 + 麦克风图标 | 待唤醒 |
| 红色 + 脉冲光圈 | 听写中 |
| 橙色 | 提交中 |
| 暗灰 + 斜杠 | 已暂停 |

说话时还会出现**浮窗预览条**，贴在光标附近显示实时文字。

## 建议按这个顺序体验

1. 右键悬浮球 → **设置...** → 切到「**演示**」页签
2. 点 **① 说「子曰」** → 浮窗弹出，文字开始逐段出现
3. 观察浮窗里的文字：**白色是已稳定的前缀，灰色是仍在变动、可能被改写的部分**
4. 点 **② 说「到此为止」** → 进入提交，浮窗显示「whisper 正在精化」
5. 稍等 → 带标点的最终文本被**一次性注入**到下面的白色输入框

### 四个值得单独试的点

**① 看"引擎改主意"**
点「重播整段流程」切到场景 2，里面有一步是 `这个需球 → 这个需求`。
这是流式识别的真实行为：引擎会回头改已经吐出的字。
**这正是我们选「浮窗预览 + 整段注入」而不是「直接打进光标」的原因** ——
否则你在屏幕上会看到字被删掉重打。

**② 验证浮窗不抢焦点（最重要）**
浮窗弹出时，点进那个白色输入框正常打字。
**如果光标被抢走、字打不进去，就是致命 bug。**
这是整个项目最容易做错、且做错了产品直接废掉的地方。

**③ 「模拟：切窗口」的行为**
结果会是：本段结束，但**注入被放弃**，提示"刚才那段没有注入成功"。
因为提交那一刻前台窗口已经变了，为避免把文字误发到别的程序，宁可丢弃。
**代价是你丢了一整段话，而且没有历史记录可找回。这条规则是否合理，值得判断。**

**④ 静音自动结束**
点①之后不说话也不点②，浮窗会显示倒计时，静音满 5 秒就自动结束本段并提交。
秒数可以在「常规」里改。

## 都是模拟的，除了这几样

| 模拟的 | 真的 |
|---|---|
| 语音识别结果（脚本逐条吐出） | **状态机** —— `StateMachine.java`，与设计一致 |
| whisper 精化的文本 | **悬浮球与浮窗都不抢焦点** —— 真窗口、真置顶 |
| 注入动作（写进本地文本框） | **右键菜单** —— 已由 Robot 自动化验证 |
| 音频（根本没有） | 日志格式与内容取舍 |

### 关于日志

日志区按**真实约定**输出：记状态流转和错误，**不记转写内容**
（所以你会看到 `len=12（内容不记录）` 这种行）。

## 自检

```
run.cmd              # 状态机自检，全绿才启动
run.cmd --ui-test    # 右键菜单自检（会移动鼠标并右键一次）
```

| 自检 | 覆盖 |
|---|---|
| `StateMachine` 24 项 | 正常流程、Esc 取消、以及重复唤醒 / 提交中迟到事件等**真实竞态** |
| UI 右键菜单 2 项 | A. 菜单能否从**不抢焦点**的窗口弹出；B. 鼠标事件能否投递到悬浮球 |

两份报告分别写入 `selftest-report.txt` 与 `ui-selftest-report.txt`（UTF-8），
控制台只输出 ASCII 摘要 —— 因为 Windows 控制台默认代码页是 GBK，
中文会乱码并掩盖真正的失败信息。

项目引入 Maven 后，这些自检应迁移为 JUnit 5 测试。

## 已知的粗糙处

- 悬浮球位置不持久化，重启回到默认位置（真实产品应写入配置）。
- 悬浮球不能隐藏，也没有贴边收起。
- **没有托盘图标**：悬浮球是退出程序的唯一入口（位置已做屏幕内夹取，不会丢）。
  真实产品是否要补回托盘图标，仍可再议。
- 设置窗口的样式仍是基础 Swing 外观。
- 浮窗位置贴的是模拟输入框或悬浮球，不是真的跟随系统光标（那需要 Win32 调用）。
- 麦克风、音频相关的一切都不存在。
