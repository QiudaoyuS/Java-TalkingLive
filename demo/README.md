# TalkingLive 交互原型（Demo）

看**界面与操作流程是否合理**用的原型。**没有实现任何真实后端** —— 没有麦克风、没有语音识别、没有 Win32 调用，所有识别结果都是脚本模拟的。

对应设计文档：`../docs/DESIGN.md`

---

## 怎么跑

双击 `run.cmd`。它会依次编译 → 跑自检 → 启动 Demo。

需要 JDK。本机已验证：`D:\Code\Java\jdk-21.0.12.1`（PATH 里的 `java`/`javac` 已指向它）。

想跳过手动点击、直接看完整流程：

```
run.cmd --auto
```

## 会看到两个窗口

| 窗口 | 是什么 |
|---|---|
| **交互原型控制台** | 用来触发各种场景。**真实产品里没有这个窗口**——它常驻托盘，没有主界面 |
| **深色浮动预览条** | 贴在「模拟光标处」输入框下方。**这才是真实产品的界面** |

---

## 建议按这个顺序体验

1. 点 **① 说「子曰」** → 浮窗弹出，文字开始逐段出现
2. 观察浮窗里的文字：**白色是已稳定的前缀，灰色是仍在变动、可能被改写的部分**
3. 点 **② 说「到此为止」** → 进入提交，浮窗显示「whisper 正在精化」
4. 稍等 → 带标点的最终文本被**一次性注入**到下面的白色输入框
5. 点 **重播整段流程** → 换一个场景再走一遍

### 三个值得单独试的点

**看"引擎改主意"** —— 点「重播整段流程」切到场景 2，里面有一步是
`这个需球 → 这个需求`。这是流式识别的真实行为：引擎会回头改已经吐出的字。
**这正是我们选"浮窗预览 + 整段注入"而不是"直接打进光标"的原因** ——
否则你在屏幕上会看到字被删掉重打。

**验证浮窗不抢焦点（最重要）** —— 浮窗弹出时，点进下面那个白色输入框，
正常打字。**如果光标被抢走、字打不进去，就是致命 bug。**
这是整个项目里最容易做错、且做错了产品直接废掉的地方。

**看静音兜底** —— 点①之后不说话也不点②，浮窗会显示倒计时，5 秒后自动提交。
秒数可以在「配置」里改。

## 都是模拟的，除了两样

| 模拟的 | 真的 |
|---|---|
| 语音识别结果（脚本逐条吐出） | **状态机** —— `StateMachine.java`，与设计一致 |
| whisper 精化的文本 | **浮窗不抢焦点** —— 真窗口、真置顶 |
| 注入动作（写进本地文本框） | 托盘图标与状态变化 |
| 音频（根本没有） | 日志格式与内容取舍 |

### 关于日志

日志区是**按真实约定**输出的：记状态流转和错误，**不记转写内容**
（所以你会看到 `len=12（内容不记录）` 这种行）。

## 内置的场景

| 按钮 | 对应设计里的 |
|---|---|
| ① 说「子曰」 | 语音唤醒 |
| ② 说「到此为止」 | 结束词 |
| ③ 静音超时 | 静音兜底 |
| 模拟：切窗口 | 切窗口 = 一段结束，且**注入会被放弃**（注入前会校验前台窗口） |
| 模拟：按 Esc | 整段取消，一个字都不注入 |
| 重播整段流程 | 切换场景重来 |

试一下 **「模拟：切窗口」** —— 你会看到提交时提示"刚才那段没有注入成功"。
这是有意设计的：提交那一刻前台窗口变了，为避免把文字误发到别的程序，
宁可放弃。**这条规则是否合理，值得你判断。**

## 自检

```
run.cmd          # 会先跑自检，全绿才启动 Demo
```

`StateMachine` 有 24 项自检，覆盖正常流程、Esc 取消、以及各种**非法事件被忽略**
（重复唤醒、提交中迟到的静音/结束词/窗口变化等真实竞态）。
详细报告写入 `selftest-report.txt`（UTF-8），控制台只输出 ASCII 摘要 ——
因为 Windows 控制台默认代码页是 GBK，中文会乱码并掩盖真正的失败信息。

项目引入 Maven 后，这些自检应迁移为 JUnit 5 测试。

## 已知的粗糙处

- **控制台窗口的样式是随手做的**，且它本身不是产品的一部分，不用细看。
- 浮窗位置是**贴着模拟输入框**算的，不是真的跟随系统光标（那需要 Win32 调用）。
- 扬声器/麦克风相关的一切都不存在。
